Getting started

Before you deploy

  • Caddy and Authentik must already be deployed. ATLAS publishes its console as a Caddy vhost behind Authentik sign-in, and registers itself as an Authentik application. ⚠️ Without Authentik the deploy still succeeds but the console vhost is not published, and the log says so.
  • A domain pointed at this box. The console lands on atlas.<your-domain>.
  • One Android tablet you can factory reset. Device Owner can only be established during the out-of-box wizard — there is no way to convert a set-up device.

1. Deploy

Press Deploy ATLAS. It clones the pinned release, builds the image, generates a device certificate authority, opens :8449 for devices, registers the Authentik application and restricts it to administrators. Seven steps, 5–10 minutes on the first run.

2. Open the console

https://atlas.<your-domain>, signing in through Authentik. The Android agent and launcher are already loaded — they ship with the release and are installed into the app library on first start, so there is nothing to upload.

3. Enrol one device

  • On the Enroll page, create an enrollment token.
  • Fill in the Wi-Fi the tablet should use while provisioning, then Generate enrollment QR.
  • On the factory-reset tablet, tap the first setup screen six times in the same spot to open the QR scanner, and scan it.
  • The tablet joins Wi-Fi, installs the agent as Device Owner, and appears on Manage within a few seconds.

⚠️ The QR expires after 15 minutes by default — it is a live credential, and a photograph of it is too. There is a permanent option for a provisioning bench, with the trade explained on the page.

4. Then use the guides inside ATLAS

The Guides section of the console covers policies, app deployment, kiosk mode, content and device identification. They live with the release, so they describe the version you are actually running.

⚠️ One security step afterwards. A new install keeps the certificate authority's root key on this server, where anyone who reaches the box can take it and mint a device identity for ever. Once ATLAS is running, the Certificate authority card on this page walks through moving it somewhere safer. Devices are unaffected and nothing needs to be touched on any tablet.

If you are locked out of ATLAS

Each of these turns off one admin check. They need an SSH shell on this server — deliberately: a button here that disabled an authentication gate would be the bypass the gate exists to prevent.

1. "must be reached through the authenticating proxy"

ATLAS is demanding the header Caddy attaches after sign-in, and is not getting it — usually a Caddyfile that has not been regenerated.

sed -i '/^TAKMDM_PROXY_AUTH_SECRET=/d' /root/atlas/.env cd /root/atlas && docker compose up -d api

2. "administrator access requires membership of …"

You signed in, but not as a member of the group ATLAS requires. Either add yourself to that group in Authentik, or stop requiring one:

sed -i 's/^TAKMDM_ADMIN_GROUP=.*/TAKMDM_ADMIN_GROUP=/' /root/atlas/.env cd /root/atlas && docker compose up -d api

3. "not within TAKMDM_TRUSTED_PROXIES"

The request reached ATLAS from an address it does not serve the console to. The log line names both what arrived and what was allowed.

sed -i 's|^TAKMDM_TRUSTED_PROXIES=.*|TAKMDM_TRUSTED_PROXIES=any|' /root/atlas/.env cd /root/atlas && docker compose up -d api

4. ATLAS will not start: "root key missing"

The certificate authority's root key was removed with nothing left to sign with. ⚠️ Do not redeploy — a fresh install mints a new CA and every enrolled device stops authenticating for good. Restore the recovery file you saved, then use Renew issuing certificate above.

Seeing why, before changing anything

docker logs --tail 50 takmdm-api-1

Every refusal above logs the reason and the setting responsible. ⚠️ Read it first: turning off the wrong gate leaves the real fault in place and removes a control for nothing.

Put back whatever you cleared once the cause is fixed. An ATLAS running without these is an MDM console — remote wipe, factory reset, policy push — trusting a header anything on this host can send.

Checking the file and removing the key…

Renew the issuing certificate

ATLAS signs device certificates with an issuing certificate. When it expires, every device stops authenticating. Renewing it needs the root key, which is deliberately not kept on this server.

Devices roll onto the new certificate by themselves — nothing needs to be done to any tablet.

Leave empty if the root key is still on this server. It is written for the length of one command and removed immediately afterwards, whether the command succeeds or fails.

Uninstall ATLAS

Removes ATLAS completely: containers, images, the database volume, the install directory, the Caddy vhosts, the firewall rule, and the ATLAS application in Authentik. Installing again rebuilds all of it from scratch.

⚠️ This destroys the device CA and the database. Every enrolled tablet's identity is signed by that CA. Once it is gone they cannot be re-adopted — each needs a factory reset, in person. There is no undo and no backup taken.
